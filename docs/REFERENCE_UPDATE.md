# Lintel / Flat to 3D 재검토와 반영 — 2026-11-09

대상은 [Lintel live](https://sam1983aing.github.io/lintel-live/)와 [Flat to 3D](https://sam1983aing.github.io/flat-to-3d/)입니다. 브라우저에서 대표 화면·조작을 확인하고, Lintel 공개 HTML과 로컬 `원본_flat-to-3d`의 7종·14개 변형 코드를 함께 대조했습니다. Lintel의 최신 화면은 기존 Casa Serra 중심 스터디 문서와 다릅니다.

## 관찰과 선택

| 관찰한 방식 | 현재 앱 판단 | 반영 |
|---|---|---|
| Lintel의 5개 실내 정지점에 설명 창·이전/다음 방 안내가 결합됨 | 공간이 중요한 순간에는 설명을 접을 수 있어야 함 | `공간만 보기`, 현재 정지점 표시, 다음 방 이름을 유지하는 축소 UI |
| Lintel은 같은 실내를 시간대별로 비교함 | 기존 아침·정오·골든아워·야간 기능을 유지 | 선택 상태의 접근성 표시, 모바일에서 이동 버튼과 겹치지 않게 배치 |
| 원본 05는 스크롤·재생·range·간트 드래그를 병행함 | 기존 간트 드래그에는 키보드 대안이 필요 | 주차 range·공정 재생, 수동 입력 시 재생 정지 |
| 원본 01·03·07의 정지점·장면 위치가 명료함 | 긴 스크롤에서 현재 위치와 직접 이동을 제공 | 10개 장면 진행률·이전/다음, 공통 `story.js` |
| 원본의 도면과 실물은 같은 형상에서 나옴 | 기존 돌리 줌·1.2m 컷·개구부 공유 구조를 유지 | 방 카드의 치수·층고도 실제 선택 층의 같은 방 객체에서 산출 |
| 원본 04·05는 공정표와 모델이 시간을 공유함 | 조작을 추가해도 금융의 준공 끝점과 일치해야 함 | 마지막 부분 주의 자금·이자 및 설비 지연 선후행 수정 |

원본 02의 스캔, 03의 단면 돌리 줌, 07의 그림자 해칭은 이미 구현돼 있어 중복 엔진을 추가하지 않았습니다. 01의 분해도는 기존 사용자 판단에 따라 삭제된 상태를 유지합니다. 06의 책상/카드 모형 세계와 07B의 가상 분양 상태는 현재 법규·공정 검토 화면의 목적과 달라 도입하지 않았습니다.

Lintel의 스튜디오 주장·해외 단가·연락 폼·사진 자산은 옮기지 않았습니다. 외부 코드를 제품 소스에 복사하지 않고, 관찰한 인터랙션 원리를 기존 ES 모듈과 FORMEQUA 디자인으로 구현했습니다. 스터디용 다운로드는 `Claude outputs/reference-study/`에 분리합니다.

## 구현 경계

- `story.js`: 카메라와 탐색 UI가 사용하는 장면 경계와 목적지.
- `main.js`: 진행률·주차 조작, 재생 중단, 설명 접기, 올바른 층의 방 선택, 비활성 레이어 inert 처리.
- `ui.js`: 같은 방 사각형에서 면적·치수·마감·층고 표시. 층고는 층간 높이이며 천장 유효높이가 아닙니다.
- `style.css`: 실제 헤더/공정 패널 높이를 반영하고 작은 화면에서도 탐색을 유지.
- `types.js` / `building.js`: 대칭 문 좌표 수정 및 벽 밖 문 틈 제한.
- `law.js`: 본체·윙·포치의 수평 배율 일치. 정원 고정 요소는 기존 부지 기준 위치를 유지.
- `project.js`: MEP 종료를 준공 전에 확인, 부분 주 자금 보간, 주5일 작업일 표시.

현행 법령·조례의 정확성, 실제 인허가, 주차 상세 동선, Revit/IFC 연동을 새로 검증하거나 구현한 작업은 아닙니다.

## 회귀 검증

`node test/fit.mjs`는 기본 6유형의 탐색 결과를 확인합니다. `node test/regressions.mjs`는 법규/모델 면적, 준공 시점의 공사비·현금흐름 끝점과 중간 보간, 4개 배율의 대칭 문 범위, 전원주택 자동 매스의 윙 면적, 설비 +8주 지연의 준공 반영, 주5일 작업일, 장면 경계를 검증합니다.

브라우저 확인 항목: 장면 이동, 주차 슬라이더의 키보드 조작, 자동 재생 중 수동 탐색, 설명 접기/복원과 다음 방 이동, 반복층 투어 카드, 유형 전환, 산정 패널, 모바일 UI 겹침. 최초 localhost 접근 실패는 localhost 전용 서버를 통해 해결했습니다.

확인 결과: 6유형 전환·첫 정지점 이동에 실행 오류가 없었고, 중소형 빌딩 2층 사무실 카드가 실제 2층을 표시했습니다. 작은 화면(CSS 폭 약 390px)에서 가로 넘침과 시간대/이동 버튼 겹침이 없었습니다. 근생의 설비 +8주 입력은 45.2주 → 52.2주로 반영됐고, 주차 슬라이더 End에서 `준공`과 공사비 집행 100%가 함께 표시됐습니다. 준공 카메라는 공정 패널 위에 건물 전체가 보이도록 프레이밍을 보정했습니다. 고품질 토글 후에도 화면이 렌더링됐으며 마지막 브라우저 오류 로그는 비어 있었습니다. 임시 테스트 탭·화면 크기 설정·서버는 정리했습니다.
