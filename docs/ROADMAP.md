# 로드맵 — 한국형 건축·개발 검토 화면

목표: **주소를 넣으면 대지가 나타나고, 적용 규정에 따른 건축 가능 규모를 보여주며, 설계안·공정·사업성까지 스크롤로 설명하는 화면.**

## 현재 (v3.5, 이 저장소)

| 영역 | 구현 상태 |
|---|---|
| 연출 | 플로터 인트로 → 입면도(45° 해칭 그림자) → 돌리 줌 + **스캔 스윕** → **법규 장면** → 공정 달력(유형별 카메라·현장 장비) → 준공 → **단면** → 평면도 1.2m 컷 → 방별 실내 투어 → 마무리 요약, 시간대 프리셋 |
| 유형 | 중소형 빌딩(업무+근생) · 다세대주택 · 임대형기숙사 · 전원주택 |
| 법규 | 용도지역별 건폐율·용적률(서울 조례), 정북 일조 이격, 대지 안의 공지(단순화), **주차 법정 대수(별표1·주택건설기준 제27조·끝수 규칙)와 구획 배치 — 필로티형은 매스 조건, 장애인 전용·확장형·서울 주차상한제**, 유형 요건(다세대·임대형기숙사) → **자동 최대 매스**(층수·평면 배율), 3D 대지 경계·일조사선·층별 건축가능영역 |
| 근거 검증 | 법령 MCP 미연결 (커넥터 추가 필요). 현재 수준: 정북 일조·다세대·임대형기숙사 정의 '확인', 서울 조례 건폐율·용적률 일부와 주차 일부 '2차자료 일치', 나머지 '검증 필요' |
| 화면 품질 | 물리 하늘·하늘 반사·GTAO·범프 재질(고품질 토글), FORMEQUA 톤 UI, 홈페이지 연결(docs/HOMEPAGE.md) |
| 판정 상태 | 적합 / 부적합 / 권고 미충족 / 확인 필요 — 항목마다 근거 조문과 검증 상태 표시 |
| 공사비·공기 | 공종별 단가·비율·마감 등급, 선후행 공정·지연 시나리오, 자기자본→PF 인출·이자유보 |

## 다음 단계 (공개 저장소 조사 반영, 2026-11-09 기준 README·라이선스 확인)

### 1단계 — 근거 계층: 법령·조례·별표
- **korean-law-mcp** (chrisryugj, MIT): 조문·별표·자치법규·연혁 조회 → `law.js` 표 검증·갱신 (docs/LAW_MCP_SETUP.md)
- **kordoc** (chrisryugj, MIT): HWP·HWPX·PDF 별표 → 표 구조화 (주차 별표, 지구단위계획 지침)
- 규칙 레코드 확장: 적용 지자체·용도 / 법령 ID·버전 / 시행일·검토 기준일·조회일 / 조문·별표 링크 / 계산식·예외 / 검토 상태·확인자
- 원칙: LLM은 근거 찾기·규칙 후보 추출·설명, **수치 판정은 검토된 규칙 + 계산 코드**

### 2단계 — 대지 계층: 주소 → 필지 → 용도지역
- VWorld API(주소·PNU·필지 폴리곤), 토지이용계획정보·토지이용규제정보 API, 주소 정규화(addresskr, Apache-2.0)
- 참고: **cadastral-mcp** (MIT) — 필지 DXF, 조례 수치 추출 흐름. 고정값 대체 동작은 '확인 필요'로 바꿔 사용
- 정형 사각형 대지 → 실제 폴리곤 대지, 정북 방향을 실제 방위로 (현재는 -z가 북쪽 고정)
- 웹에서 공공 API를 직접 부르면 키 노출·CORS 문제 → 작은 중계 서버(예: Cloudflare Worker) 필요

### 주차 고도화 (2·3단계와 함께)
- 서울 조례 별표3 상한 비율·장애인 비율 원문 확정(법령 MCP), 경형 10% 인정, 장애인등편의법상 공동주택 기준
- 지하 자주식 램프 배치(대지가 클 때), 기계식 형식별(승강기식·퍼즐·다단) 수용 대수와 공사비 단가 표
- 실제 폴리곤 대지에서 진입 방향·도로 조건(보·차도 구분, 12m 기준)

### 3단계 — 형상 계층: 건축가능영역 고도화
- 참고: **TranslateZoning2BuildableVolume** (snu-laus, MIT): 규정 → RASE JSON → 층별 허용 폴리곤 (Rhino/Grasshopper 의존 → 웹용 로직은 이식 필요)
- 계단식 셋백(층마다 북측을 물리는 매스), 도로사선·가로구역 높이, 지구단위계획 높이·용적률
- 면적 종류 분리: 연면적 / 용적률 산정용 / 전용·공용 / 임대·분양 (건축법 시행령 제119조)

### 4단계 — 실제 설계 모델
- **ThatOpen engine_components**(MIT) + **web-ifc**(MPL-2.0): IFC 로드, 층·공간·부재 선택
- **IfcOpenShell / IfcTester**(LGPL 계열): 서버에서 공간·부재 추출, IDS로 속성 누락 검사 (기하 검사는 별도 계산)
- 부재 ID ↔ 공정(WBS) ↔ 물량·원가 연결 → Exploded / Open Section 기법을 실제 모델로

### 5단계 — 사업성
- 공정률 / 기성 인정액 / 실제 지급액 / 대출 인출액을 **각각** 관리
- 분양·임대 수입 일정, 날짜별 현금흐름 → XIRR·XNPV (**pyxirr**, Unlicense 등)
